title: 레거시 프론트엔드 전환을 통해 배운 기술적 의사결정
tags: [React, 레거시 전환, 기술 선택]
---

> 핵심 역량: 레거시 프론트엔드를 전환하며, 기술의 생태계뿐 아니라 개발 규칙과 장기적인 유지보수 가능성까지 고려해야 한다는 기준을 얻은 경험입니다.

입사 당시 서비스의 프론트엔드는 AngularJS 기반이었습니다. 관련 개발 자료와 커뮤니티 지원이 제한적이었고 공식 지원 종료도 예정되어 있어, 유지보수와 향후 기능 확장을 위한 기술 전환이 필요했습니다. Vue와 Angular도 함께 검토했으며, 개발자 기반과 커뮤니티가 활발해 문제 해결에 필요한 자료와 선택지를 확보하기 좋다고 판단한 React로 전환을 추진했습니다.

저는 채팅방 목록, 메시지 목록, 메시지 작성 등 서비스의 기본 화면을 React로 이전하는 작업을 맡았습니다. 기존 기능을 React 기반으로 옮겨 이후 개발에 해당 생태계의 라이브러리와 참고 자료를 활용할 수 있는 기반을 마련했습니다.

다만 촉박한 일정 속에서 기능 이전에 집중하면서 초기 디렉터리 구조와 파일 네이밍 규칙을 충분히 표준화하지 못했습니다. 당시 TypeScript 경험이 부족해 JavaScript로 전환을 진행한 점도 아쉬움으로 남았습니다. 기능 이전 계획과 함께 개발 규칙을 정하고 TypeScript 학습·적용 범위를 단계적으로 설계했다면, 전환 이후의 유지보수까지 더 체계적으로 준비할 수 있었을 것입니다. 현재는 신규 파일을 TypeScript와 TSX로 작성하며 타입 검사를 적용하는 범위를 넓히고 있습니다.

상태 관리 라이브러리의 지속성도 돌아보게 되었습니다. 전환 당시에는 Recoil을 선택했지만, 이후 개발이 중단되면서 2025년 Jotai 전환을 진행하고, 2026년에는 남아 있던 Recoil 사용처와 의존성을 정리했습니다. 이를 통해 프레임워크의 생태계뿐 아니라 함께 도입하는 라이브러리의 유지보수 상태와 향후 교체 가능성도 검토해야 한다는 점을 배웠습니다. 앞으로는 기술 도입 시 기능 이전 범위와 함께 개발 규칙, 타입 적용 계획, 의존 라이브러리의 지속성까지 검토 기준으로 삼겠습니다.
