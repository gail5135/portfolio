> 핵심 역량: 팀의 개발 역량에 맞춰 클라이언트를 Electron으로 전환하고, 웹 개발자가 데스크톱 기능까지 개발·유지보수할 수 있는 기반을 마련한 경험입니다.

기존 클라이언트는 Windows 네이티브 애플리케이션 안에서 WebView2로 웹 화면을 실행하는 구조였습니다. 조직 개편으로 Windows 클라이언트 개발자가 없어지면서 네이티브 기능을 추가하거나 수정하기 어려워졌습니다. 이에 팀이 활용할 수 있는 JavaScript 기반으로 데스크톱 기능을 개발할 수 있도록 Electron을 조사하고 도입하기로 결정했습니다.

전환 과정에서 저는 기존 WebView2 기반 화면을 Electron의 렌더러 프로세스에 연동하는 작업과 앱 잠금 모드, 딥 링크 기능 개발을 맡았습니다. 메인 프로세스가 애플리케이션의 기본 틀을 담당하고 렌더러 프로세스에서 기존 웹 화면 코드를 활용하도록 구성했습니다.

전환의 효과는 창 위치와 크기를 제어하는 작업에서 드러났습니다. 노트북에 외부 모니터를 연결하거나 해제할 때 채팅방 창의 위치가 어긋나는 문제가 있었는데, 기존에는 Windows 네이티브 코드를 수정해야 대응할 수 있었습니다. Electron 도입 후에는 웹 개발자도 창 위치와 크기를 직접 제어할 수 있어 이러한 문제에 대응하기 쉬워졌습니다.

로컬 파일이나 운영체제와 연동하는 기능도 개발했습니다. 앱 잠금 모드는 설치 폴더 경로를 읽고 잠금 파일을 생성한 뒤 암·복호화와 유효성 검사를 수행해야 했습니다. Electron을 통해 이 작업을 구현해 잠금 모드를 지원했으며, 외부 링크로 클라이언트를 실행하는 딥 링크 기능도 개발했습니다. Windows와 macOS에서 동일한 기능을 제공하도록 개발했고, macOS 지원 버전은 사용하는 Electron 버전에 따라 달라지는 조건을 고려했습니다.

다만 기존 화면이 단일 페이지 애플리케이션(SPA) 구조가 아니어서 여러 렌더러 프로세스를 관리하는 어려움은 남아 있습니다. 이를 개선하기 위한 후속 목표로 SPA 전환을 두고 있습니다. 이번 전환으로 팀이 직접 유지보수할 수 있는 범위를 데스크톱 기능까지 넓혔으며, 남은 화면 구조 개선은 별도의 과제로 정리했습니다.
