> 핵심 역량: AI 기능을 이용하고 운영하는 프론트엔드를 개발하고, AI 도구로 구현한 결과를 직접 테스트하며 검토한 경험입니다.

### Fireside의 AI 대화 기능과 운영 화면 개발

Fireside의 AI 챗봇과 Text-to-SQL Agent 도입 과정에서 메신저 클라이언트와 관리자 콘솔의 프론트엔드 개발을 담당했습니다. 메신저 클라이언트에서는 사용자의 메시지를 전송하고 AI 응답을 표시하는 화면을 구현했습니다. 슬래시 명령어로 호출하는 챗봇은 관리자 콘솔에서 등록·수정할 때 호출 명령어도 함께 설정할 수 있도록 했습니다.

Text-to-SQL Agent는 사용자의 질문에 맞는 SQL을 생성하고, 쿼리 실행 결과를 바탕으로 답변하는 기능입니다. 저는 관리자가 Agent에 사용할 데이터베이스를 등록하고 테이블·컬럼 설명을 보강하는 화면을 구현했습니다. 에이전트 질의응답 로그는 테이블 형식의 목록과 검색 필터, 개별 로그의 상세 화면으로 구성했습니다. 사용자가 답변에 남긴 피드백도 로그에서 확인할 수 있도록 해, 관리자가 설명 보강에 참고할 수 있게 했습니다.

대화 화면에는 응답이 생성되는 과정을 볼 수 있는 스트리밍 UI와 Markdown 렌더링을 적용했습니다. 사용자에게 익숙한 AI 대화 방식을 제공하고, 답변에 포함된 서식을 화면에 표현하기 위해서였습니다. 구현 과정에서는 한국어 문장에서 Markdown 문법 바로 뒤에 조사가 붙을 때 서식이 적용되지 않는 사례를 발견했고, 해당 사례를 고려해 렌더링 처리를 보완했습니다.

### AI 구현·리뷰 도구를 활용한 개발 워크플로우

실제 기능 개발에는 Claude Code로 구현하고 Codex로 리뷰하는 작업 흐름을 적용했습니다. 먼저 기획서나 직접 정리한 요구사항을 바탕으로 Claude Code에 기능 사양과 작업 계획 정리를 요청했습니다. 사양은 GitLab 이슈에, 작업 계획은 MR(Merge Request)에 기록한 뒤 구현을 진행했습니다.

구현이 끝나면 Codex에 리뷰를 요청하고, 발견된 이슈를 Critical, Important, Minor 세 단계로 분류했습니다. Critical과 Important 이슈는 우선 검토하되, Critical 중 문제가 심각하거나 변경 규모가 큰 경우에는 별도 GitLab 이슈를 작성해 처리했습니다. Minor 이슈는 필요성을 검토해 반영 여부를 결정했습니다. 반영할 이슈는 사양과 작업 계획에 정리한 뒤 Claude Code에 수정을 요청하고, 수정 대상으로 정한 항목이 해결될 때까지 반복했습니다.

이 흐름을 적용한 사례로 메시지 목록의 윈도잉 작업이 있습니다. 메시지 목록과 입력창이 Jotai 상태를 공유해, 메시지를 입력할 때마다 목록도 함께 리렌더링되고 메시지가 많아질수록 입력이 버벅이는 문제가 있었습니다. 공유 상태를 분리하는 방안은 기존 기능에 미칠 영향이 크다고 판단했습니다. 또한 메시지 검색이나 위로 스크롤해 이전 메시지를 추가로 불러오는 상황에서도 렌더링할 메시지가 늘어나면 성능 문제가 발생할 수 있었습니다. 이에 여러 사용 상황에서 목록의 렌더링 부담을 줄일 수 있도록, 화면에 보이는 범위 중심으로 메시지를 렌더링하는 윈도잉을 선택했습니다.

AI가 구현한 결과를 테스트하던 중, 일반·파일·이미지 메시지처럼 높이가 서로 다른 항목이 한꺼번에 로딩될 때 초기 스크롤 위치가 맞지 않는 현상을 발견했습니다. 대화 화면을 처음 열면 최신 메시지가 있는 맨 아래에 위치해야 했지만, 목록 중간에 머무는 경우가 있었습니다. 이 증상을 텍스트와 화면 캡처로 설명하고, 재현 순서와 로그를 함께 전달해 수정을 요청했습니다. 수정본을 받으면 다시 테스트하고 정상 동작 여부를 전달하는 과정을 반복했습니다.

최종 결과는 제가 직접 확인한 후 MR을 승인했습니다. AI 도구를 사양 정리부터 구현과 리뷰까지 활용하면서도, 실제 동작 검증과 리뷰 의견의 반영 여부, 최종 승인 판단은 직접 맡았습니다.
