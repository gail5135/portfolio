# 설계 결정 기록

이 사이트를 만들면서 내린 결정과 그 이유를 남긴다.
코드를 읽으면 "무엇을" 했는지는 알 수 있지만 "왜"는 남지 않기 때문이다.

## 저장소와 배포

**프로젝트 사이트로 배포한다.** `gail5135/portfolio` → `https://gail5135.github.io/portfolio/`

하위 경로로 서빙되므로 `vite.config.ts` 에 `base: '/portfolio/'` 가 반드시 있어야 한다.
이 값을 지우면 빌드는 성공하지만 배포된 페이지에서 CSS 와 JS 가 404 로 실패한다.
증상이 조용해서 놓치기 쉽다.

`main` 에 push 하면 `.github/workflows/deploy.yml` 이 빌드해서 Pages 로 올린다.
Pages 는 GitHub Actions 방식으로 설정돼 있다 (브랜치 방식 아님).

무료 계정에서 Pages 를 쓰려면 저장소가 public 이어야 한다.

## 기술 선택

**Vite + React + TypeScript + SCSS Modules**

React·Vite·Electron·SASS 실무 경험과 같은 스택이다. 포트폴리오 사이트를
평소 쓰지 않는 스택으로 만들 이유가 없다.

사이트 소스 자체가 결과물의 일부이므로, 컴포넌트 분리와 타입 정의가
저장소에서 바로 보이는 편이 낫다고 판단했다.

**넣지 않은 것**: 라우터, 상태관리 라이브러리, UI 컴포넌트 라이브러리.
단일 페이지에 불필요하다. 의존성은 적을수록 좋다.

## 콘텐츠를 마크다운으로 두는 이유

`content/` 의 마크다운 파일이 사이트의 모든 글이다. `src/` 에는 글이 없다.

처음에는 TypeScript 데이터 파일에 글을 넣는 안을 검토했으나 버렸다.
여러 문단짜리 글을 문자열 리터럴로 쓰면 따옴표 이스케이프와 `\n\n` 이
쌓이고, 쉼표 하나가 빠지면 빌드가 깨진다. 글을 자주 고칠수록 부담이 커진다.

마크다운으로 두면:

- 문법 오타로 빌드가 깨지지 않는다
- 소제목·문단·목록의 구분을 마크다운 문법이 대신하므로
  `highlights` / `bullets` 같은 필드를 따로 둘 필요가 없다
- GitHub 웹 편집기로 바로 고칠 수 있다. 로컬 클론과 빌드가 필요 없다

**원칙**: 바뀔 수 있는 값은 전부 `content/` 에 있어야 한다. 예외를 두지 않는다.
회사 재직 기간이 `src/` 가 아니라 `content/companies.yml` 에 있는 것도 이 때문이다.

## 파싱은 빌드 타임에

`plugins/content.ts` 가 `.md` 와 `.yml` 을 빌드 시점에 파싱해 JS 모듈로 바꾼다.

처음에는 브라우저에서 파싱했는데, 그러면 `js-yaml`(128KB)과 `marked`(44KB)가
번들에 통째로 들어간다. 정적 사이트라 파싱 결과가 빌드 시점에 고정되므로
런타임에 다시 할 이유가 없다.

옮긴 결과 번들이 297KB → 210KB (gzip 94KB → 68KB) 로 줄었고,
두 파서는 `devDependencies` 로 내려갔다.

파일 하나가 깨져도 빌드를 세우지 않는다. 경고를 남기고 그 파일만 건너뛴다.
글 하나의 오타로 배포 전체가 막히면 안 되기 때문이다.

## Work Experience 와 Work Timeline 을 나눈 이유

처음에는 한 섹션이었다. 나누기로 한 것은 두 글의 읽는 목적이 다르기 때문이다.

- `content/experience/` — 무엇을 배웠고 왜 그렇게 판단했는지. 읽히려고 쓰는 글.
- `content/timeline/` — 무엇을 했는지의 목록. 사실 위주.

Experience 를 Timeline 보다 위에 둔다. 먼저 읽혀야 하는 쪽이다.

마크다운 본문의 헤딩 레벨은 폴더에 따라 다르게 내린다.
Experience 는 글 제목이 h3 이라 본문 `##` 이 h4 가 되고,
Timeline 은 프로젝트 제목이 h4 라 `##` 이 h5 가 된다.
`plugins/content.ts` 의 `headingOffset` 이 이 처리를 한다.

## 전화번호를 넣지 않는다

**의도적으로 뺐다.** 저장소가 public 이라 크롤러가 수집한다.
연락은 이메일과 GitHub 으로 받는다. 전화번호는 이력서로만 전달한다.

나중에 "연락처가 비어 있네" 하고 다시 넣지 않도록 여기에 남긴다.

## 만들지 않기로 한 것

- **PDF 저장 / 인쇄 버튼** — 필요해지면 그때 만든다
- **콘텐츠 입력 폼 화면, 템플릿 생성 CLI** — 파일 직접 편집으로 충분하다고 판단
- **GitHub API 로 저장소 자동 나열** — 이 사이트는 저장소 쇼케이스가 아니다
- **라우팅 / 다중 페이지, 블로그, 방문자 분석**
- **과한 스크롤 애니메이션**

## 화면 원칙

이력서형 단일 컬럼. 장식보다 가독성.

- 본문 최대 폭 `--measure` (46rem)
- 색은 무채색 기반 + 강조색 하나. 값은 전부 `src/styles/tokens.scss` 의 CSS 변수
- 다크모드는 `prefers-color-scheme` 대응. 토큰 값만 바꾼다
- 모바일 375px 에서 가로 스크롤이 생기지 않아야 한다
  (내비가 넘칠 때는 내비 안에서만 가로 스크롤)
- 헤딩 위계를 건너뛰지 않는다. 스킵 링크를 둔다
